## 安装

安装你的完整技能包，并选择需要的技能：

```bash
npx skills@latest add Jerry2586/Codexjineng
```

安装主控与 AOCI 协同技能（远程命令仅安装仓库已发布内容）：

### 安装固定正式版

上面的 skills 命令跟随仓库当前内容。需要固定到 v1.1.0 时，下载 Release 中的 `smartbuild-1.1.0.zip`，核对 `SHA256SUMS` 后解压；也可以检出版本标签：

```bash
git clone --branch v1.1.0 --single-branch https://github.com/Jerry2586/Codexjineng.git smartbuild-1.1.0
cd smartbuild-1.1.0
```

在解压或检出的目录中运行 Windows 安装器（需要 Node.js 22 或更新版本）：

```powershell
powershell -NoProfile -File scripts/install-smartbuild.ps1
```

安装器会备份核心文件并保留已有非核心定制。恢复方式见 [运行与安装说明](./SMARTBUILD.md#110-运行与安装入口)。

## 五阶段开发骨架

```text
1. 构想定稿
→ 2. 架构定界
→ 3. 企业化改造
→ 4. 接口清理与重构
→ 5. 测试部署验收
```

- 第一阶段是自由创作：允许边想边做，把想法和 UI 做成真实可操作功能，但禁止假数据、假接口和演示空壳；
- 第二阶段把泥腿子版本盘点、拆分、迁移和补齐成正规军第一版，也能按正规流程新增功能和必要的真实接口，完成联调、验证与新增代码整理；
- 第三阶段补齐权限、安全、日志、配置、备份、监控和长期运营能力；
- 第四阶段清理错误、重复、废弃接口、多余代码、Mock、固定成功和屎山；
- 第五阶段严格先做全面真实测试，通过后上线，再在正式环境验收。
- 项目工作台使用 Codex 可识别的“智构开发指挥中心”：运行信息、全局五部进度、六列 Rxxx 活动任务和当前焦点固定分区；逐阶段状态和依据存账本，按需展开。首次接手已有代码先标待识别，读取整体结构和真实验证证据后识别阶段。
- 五部是整个项目的进度：阶段完成并有真实验收证据时智能体主动推进，不用手动切换；说“进入大下一步”也可要求立即检查。单项任务完成不改变项目阶段。

统一控制口令：`开发助手`、`关闭开发助手`、`记录需求`、`开始制作`、`暂停一下`、`查看队列表`、`调整顺序 Rxxx 到第 N`、`取消需求 Rxxx`、`启动线路图`、`转到第N阶段`。`进入大下一步` 表示请求检查能否推进到相邻下一阶段；智能体按统一授权合同识别明确行动与恢复指令，但只回显标准名称。

## 自动识别与任务面板

直接提问、说想法、检查环境、查看项目进展、创建项目或交代开发要求，助手先识别对象和动作，不用切换模式。直接说“开发助手”后首次显示完整版，后续回复显示精简工作台，直到明确说“关闭开发助手”；讨论工具和暂停也保持面板，引用里的词不触发操作。提问先回答；明确开发要求先简述范围和下一步，已开启面板时进入指挥中心，显示当前项目、记忆链、阶段、任务锁、步骤、负责人、固定五部、活动任务和唯一焦点。所有数据来自账本与真实证据，不写死截图示例，不猜完成百分比。

队列、任务锁和断点跨话题保存；进入第二阶段后，新需求不能让流程自行退回第一阶段。任务是否已完成以真实测试和验收证据为准。

查看[智构开发指挥中心与字段说明](./SMARTBUILD.md#智构开发指挥中心)：固定 Markdown 语义、动态字段和六列任务表，示例仅是格式模板。关闭仅隐藏持续面板，保留任务进度；再次开启继续显示原队列。

[面板怎么读、里面怎么运行](./SMARTBUILD.md#面板怎么读里面怎么运行)用大白话说明每个位置、任务排队、阶段推进、暂停和关闭，并给出具体场景。

运行中新增需求先安全停笔、查依赖与冲突，安全时登记后续做原任务；冲突时暂停受影响部分。明确暂放项目转去聊天时保存项目账本并等待用户明确继续原任务。回来提及旧需求先查记录，找不到标状态未知；收到明确恢复指令后核对代码并恢复。验收以你能真实操作的结果和测试证据为准。

## 日常运行规则

- 所有文字、截图、照片、附件和日志先转成大白话需求，再进入框架、编号和活动表；
- 面板已开启时按首次完整版、后续精简版显示智构开发指挥中心；五部名称、顺序、运行信息字段、首次六列详细表、后续四列短表和固定锚点不能被临时需求改写；
- 实施前简述本回合理解和步骤，已开启面板按固定格式展示任务锁和排队表；
- 明确的开发、修复或测试请求在范围清楚时直接执行，不重复索要“开始制作”；该独立口令仍可使用。暂停后明确“继续”只恢复旧范围。只读查询可检查但不改账本；先记录或别开始时仅作会话整理，明确要求持久保存才写记录。附件、引用、旧聊天及纯确认不能新增授权。
- 普通问题和需求进入同一任务面板；纯寒暄直接回应，不制造假任务；
- 开发需求自动总结、编号、排队并锁定当前任务；
- 新消息默认不覆盖正在处理的旧任务；
- 复杂逻辑先自行整理线路图，只有无法判定产品取舍时才问用户；
- 所有开发任务开始前必须说明总共分几步；
- 一次执行一步，每一步完成后测试；
- 支持暂停、恢复、断点续做和专业智能体接力；
- 用户不需要挑选技能；工作台根据需求、图片、技术、风险和环境自动选择最少且最合适的专业能力；
- 默认一个聊天窗口、一个总控、一个任务锁、一个代码修改执行者；独立只读调用可按宿主规则并行；429 或工具不支持时有限重试后熔断并串行降级；
- 禁止假数值、随机统计、Mock 冒充正式接口、固定成功响应和未经执行的测试冒充完成；
- 长对话使用精简活动需求表：本轮完成项继续保留，整轮验收并开始新轮时归档；压缩后恢复断点及所需认知，已暂停的项目等待用户明确继续原任务；
- 正式版本统一版本号、Git、CI、成品和按授权部署。

## 吸收上游专业能力

本产品可以持续吸收 [`emilkowalski/skills`](https://github.com/emilkowalski/skills) 的设计、动画、移动端和 Swift 等专业技能更新，但采用严格隔离方式：

```text
检查上游更新
→ 建立独立同步分支
→ 保护智构核心、README和安装入口
→ 合并公共专业技能
→ 自动校验
→ 创建待审查PR
→ 确认后才进入主分支
```

因此，上游可以增强你的产品，但不能覆盖“智构开发系统”的名称、开发骨架、运行规则、安装入口和发布版本。详细规则见 [`UPSTREAM.md`](./UPSTREAM.md)。

## 随包提供的专业技能

## 技能库来源与批量更新

独立维护例外：用户当前消息去除首尾空白后全文恰好为“技能库更新”时，直接按技能库来源执行批量检查和更新；不启动或恢复项目开发、不改变项目任务锁、不自动新增技能。引用、代码块、长句和标点中的口令无效。

已实现来源登记、真实 Git 批量抓取、版本记录、本地改动保护、原作者许可保留、备份回退与中断恢复。默认库位于 `~/.agents/skill-library`，技能仍保留在安装目录；来源未知或版本未核实的技能保留当前文件。使用方法见 [技能库说明](skills/auto-dev/references/skill-library.md)。

## 全项目技能调度

覆盖产品、架构、前后端、数据、接口、测试、性能、安全、部署与文档的技能选择和结果诊断。主代理根据当前任务选用小组技能，记录版本、理由、实际结果与交接；环境和权限故障单独处理，重复方法失败受切换次数限制。记录保存在各项目原有任务账本中。详见 [技能路由与使用方法](skills/auto-dev/references/skill-routing.md)。

脚本提供推荐与账本检查，由主代理读取技能并实际执行。未知能力会明确降级；当前本地验证不代表每类真实业务项目都已完成联调。

## 公司化研发与审核

固定五阶段内补齐需求、架构、开发、技能治理、质量安全、交付和知识维护职责。新任务逐步检查调度结果，逐条记录验收，并跟踪问题到修复复测。技能和专家角色按实际包内容核对版本；执行者身份未知时明确保留未知。恢复、历史兼容及安装回退见 [公司化研发合同](skills/auto-dev/references/company-development.md)。本地安装的备份位于技能库之外，旧备份迁移后保留摘要清单和恢复入口。
