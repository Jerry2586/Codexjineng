## 五阶段开发骨架

```text
1. 构想定稿
→ 2. 架构定界
→ 3. 企业化改造
→ 4. 接口清理与重构
→ 5. 测试部署验收
```

- 第一阶段是自由创作：允许边想边做，把想法和 UI 做成真实可操作功能，但禁止假数据、假接口和演示空壳；
- 第二阶段把泥腿子版本盘点、拆分、迁移和补齐成正规军第一版，也能按正规流程新增功能和必要的真实接口，完成联调、验证与新增代码整理；
- 第三阶段补齐权限、安全、日志、配置、备份、监控和长期运营能力；
- 第四阶段清理错误、重复、废弃接口、多余代码、Mock、固定成功和屎山；
- 第五阶段严格先做全面真实测试，通过后上线，再在正式环境验收。
- 项目工作台沿用第一版照片式面板：顶部一行固定五部、下一行当前阶段，下面直接是五列 Rxxx 任务表；逐阶段状态和依据存账本，按需展开。首次接手已有代码先标待识别，读取整体结构和真实验证证据后识别阶段。
- 五部是整个项目的进度：阶段完成并有真实验收证据时智能体主动推进，不用手动切换；说“进入大下一步”也可要求立即检查。单项任务完成不改变项目阶段。

统一控制口令：`记录需求`、`开始执行`、`暂停一下`、`继续执行`、`查看队列表`、`调整顺序 Rxxx 到第 N`、`取消需求 Rxxx`、`启动线路图`、`转到第N阶段`。`进入大下一步` 表示请求检查能否推进到相邻下一阶段；智能体能识别同义说法，但只回显标准名称。

## 自动识别与任务面板

直接提问、说想法、检查环境、查看项目进展、创建项目或交代开发要求，助手先识别对象和动作，不用切换模式。直接说“开发助手”后每次回复都显示完整工作台，直到明确说“关闭开发助手”；讨论工具和暂停也保持面板，引用里的词不触发操作。提问先回答，下方有同一张任务队列表；明确开发要求先显示固定五部、当前阶段，再显示照片式五列任务面板：顺序、状态、编号、所属步骤、完成内容。负责人和唯一下一步写在表格下方。

队列、任务锁和断点跨话题保存；进入第二阶段后，新需求不能让流程自行退回第一阶段。任务是否已完成以真实测试和验收证据为准。

## 日常运行规则

- 所有文字、截图、照片、附件和日志先转成大白话需求，再进入框架、编号和活动表；
- 开发要求固定置顶显示五部一级目录和当前阶段，再显示照片式五列任务面板；五部名称、顺序和运行逻辑不能被临时需求改写；
- 所有开发动作和工具调用前，必须先显示本回合理解、排队表、任务锁和总步数；
- 一次说清楚的明确开发命令先入表再直接执行；没说完、要求先记录或说别开始时，零工具等待；
- 普通问题和需求进入同一任务面板；纯寒暄直接回应，不制造假任务；
- 开发需求自动总结、编号、排队并锁定当前任务；
- 新消息默认不覆盖正在处理的旧任务；
- 复杂逻辑先自行整理线路图，只有无法判定产品取舍时才问用户；
- 所有开发任务开始前必须说明总共分几步；
- 一次执行一步，每一步完成后测试；
- 支持暂停、恢复、断点续做和专业智能体接力；
- 用户不需要挑选技能；工作台根据需求、图片、技术、风险和环境自动选择最少且最合适的专业能力；
- 默认一个聊天窗口、一个总控、一个任务锁、一个工具通道和一个代码修改执行者；429 或工具不支持时有限重试后熔断并串行降级；
- 禁止假数值、随机统计、Mock 冒充正式接口、固定成功响应和未经执行的测试冒充完成；
- 长对话使用精简活动需求表：未完成项保留，完成项下一回合移出，压缩后直接从断点续做；
- 正式版本统一版本号、Git、CI、成品和按授权部署。

## 吸收上游专业能力

本产品可以持续吸收 [`emilkowalski/skills`](https://github.com/emilkowalski/skills) 的设计、动画、移动端和 Swift 等专业技能更新，但采用严格隔离方式：

```text
检查上游更新
→ 建立独立同步分支
→ 保护智构核心、README和安装入口
→ 合并公共专业技能
→ 自动校验
→ 创建待审查PR
→ 确认后才进入主分支
```

因此，上游可以增强你的产品，但不能覆盖“智构开发系统”的名称、开发骨架、运行规则、安装入口和发布版本。详细规则见 [`UPSTREAM.md`](./UPSTREAM.md)。

## 随包提供的专业技能

除核心 `auto-dev` 外，仓库还包含来自上游并持续同步的 UI、动画、移动网页、Swift 等专业技能。它们保留各自的来源与专业定位，由智构开发系统按实际任务选择使用。

### 开关边界

开启使用第一版面板和开发助手流程；暂停保留队列与断点。关闭则停止旧执行、清空活动队列、任务锁、断点、旧授权和运行阶段，恢复普通对话，不显示任务面板，也不自动继续旧要求。重新开启重新识别本次需求及实际项目阶段。关闭不删除代码和 Git 历史；普通开发请求只处理本条明确授权范围。
