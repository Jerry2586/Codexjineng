# AOCI 项目认知协同

本技能负责 AOCI 与主任务的衔接。任务编号、授权、任务锁和业务验收由 auto-dev 或宿主现有流程管理；本技能不创建第二个任务锁，不复制 AOCI 内部事务状态机。

## 进入和返回

输入：目标项目绝对路径、当前任务与范围、实施授权、当前会话/压缩代次、已有证据引用。先确认这一步是环境检查、首次建索引、加载认知、恢复还是维护。实际工具名、参数与下一动作以当前安装版本的能力和运行时 Guide 为准。

返回：实际项目、服务版本、认知身份、交付是否完整、严格认知确认结果、治理对齐/恢复状态、证据位置、限制和唯一下一步。交付、严格确认、治理、业务测试分别报告；不生成“掌握百分比”。

## 工作流程

1. 检查可用工具和环境。按需运行 `node <本技能>/scripts/probe-aoci.mjs <项目> <受信任二进制绝对路径>`；输出只证明 CLI 和文件的存在。再核对真实 MCP 响应的仓库及服务版本。项目不符先停止认知操作；文件存在或 CLI 成功不等于 MCP 已连接。
2. 读取本项目 AOCI Rules 和实时 Guide。版本不匹配时读该版本说明；不要把参考文档的参数直接套在旧二进制上。无 MCP 时记录不可用及接入动作；已授权且范围可用源码验证的独立工作可继续，依赖认知的步骤保留阻塞。
3. 首次建立与当前会话完整读取按实际 Guide 执行。按返回游标连续接收全部片段，再完成宿主交付确认与认知确认；`check_only`、局部检索、旧收据和手读索引均不能冒充完整交付。被截断或跨版本混合的内容不能记为通过。
4. 主代理亲读即将修改的源码、约束与必要测试；AOCI 给出定位和影响依据，不能替代源码或业务验证。
5. 已知上下文压缩时更换宿主会话代次，报告真实压缩事件并依运行时恢复。收到容量限制或允许基于源码继续的明确结果时，记录限制，只继续可界定的当前任务；不自动反复加载，也不宣称全系统认知已通过。
6. 代码和测试稳定后按 Guide 维护变化对象。读取真实终态及对齐证据；`stopped` 不代表未写入，先按运行时证据核对恢复/第三方冲突，再恢复原事务。保留已经通过的业务证据，仅重做受影响步骤。
7. 将结果交回原任务。原任务只有在适用的业务验证、认知维护及约定交付全部通过后才完成。未知或未执行的结果保留未验证。

初始化、升级和配置修改按用户已有授权及文件权限执行；需要宿主重新加载时明确说明具体缺失能力。不要覆盖其它 MCP、AGENTS 内容、索引基线或已有用户改动。
