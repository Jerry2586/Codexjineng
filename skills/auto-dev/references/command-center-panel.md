# 智能体开发指挥中心面板合同

本文件定义工作台开启后的固定显示结构。目标是让人一眼看懂，也让 Codex 在长对话压缩、新会话恢复和自动测试中稳定解析。视觉质感来自清晰分区、状态图标和紧凑信息层级；真正的颜色、背景和终端皮肤由客户端决定，技能不得声称能强制聊天客户端渲染黑色面板。

## 固定结构

开启工作台后，每次回复以 `【开发助手｜框架内执行】` 开头，并按以下顺序输出。标题、字段名和表头是机器识别锚点，不得自行改名、调序或用字符画替代。尤其 `### 本回合理解` 是固定标题：普通问答也不得改成“本回合答复”“回答”或其它近义标题。

## 动态数据规则

- 所有值来自当前项目账本、工作区事实、实际工具结果或用户刚确认的内容。不得把模板里的项目名、R 编号、阶段或任务复制成真实状态。
- `本回合理解` 是固定语义区段，位于全局五部进度和活动任务之间；标题必须逐字写成 `### 本回合理解`。开发请求说明结果、边界和完成条件；普通问答在此直接写问题结论，不得改标题或借此凭空新增产品需求。
- 当前阶段只高亮一个；未知时五部仍按固定顺序显示，但写 `当前阶段：待识别`，不猜阶段。
- `智能体状态` 表示任务运行状态；`当前记忆链` 表示项目账本是否实际加载或成功保存。没有读到账本时不能写“已加载”。
- `当前任务锁` 只能有一个。没有活动任务时写 `无`，不得虚构 Rxxx、步骤、负责人、进度或完成结果。
- `当前步骤` 只显示有依据的 `n/N`。不得猜测百分比，也不得从聊天长度、代码行数或主观感觉计算进度。
- `最近完成` 最多显示本轮刚完成的一条；进入下一开发回合时从活动任务表移出。历史结果留在 Git、Issue、Release 或验证记录，不长期占用面板。
- `已取消/已结束` 的未完成项也只在取消当回合显示一次；取消回复必须说明下一开发回合将其移出活动表并保留简短历史，禁止写成已完成。
- `执行中` 只显示当前任务锁；`待执行` 默认显示队首三条，剩余用“另有 N 项，使用 `查看队列表` 展开”概括。`查看队列表` 时显示全部活动项。
- 新需求先去重并排到现有锁后面。只有用户明确调整顺序或新要求与当前方案冲突时，才改变锁或暂停受影响部分。
- 当前任务完成并有证据后，更新为 `✅ 最近完成`，队首下一项自动成为 `🔄 执行中`；没有实施授权时只能成为待确认/待执行，不能自动开工。
- 暂停时保留任务锁、当前步骤和断点；`当前焦点` 的下一步写恢复动作。关闭工作台只隐藏面板，不清空任何数据。

## 空状态与降级

- 没有活动任务时，`活动任务` 下写 `暂无活动任务`；运行信息仍保留，当前焦点写 `当前任务：无` 和真实的唯一下一步。
- 项目不明确时写 `当前项目：待确认`，只询问项目位置，不搬用其它项目的数据。
- 窄屏或输出需要精简时，仍必须保留全部标题、运行信息字段、六列任务表头和当前焦点字段；可以减少任务行数量，不能改成依赖字符位置的 ASCII 边框。
- 普通入口从未开启工作台时可以使用简表；一旦开启，问答、记录、暂停和元讨论都使用本合同的完整面板，直到明确关闭。

## 禁止事项

- 禁止用字符画边框、颜色、粗体或图标作为唯一语义；Codex 必须能从标题、字段名和表头恢复状态。
- 禁止显示无证据的百分比、假进度、假完成、假测试、假负责人或假记忆链。
- 禁止把图片示例中的 APPGOGCMS、R004、R005、R006 或任何示例任务写死。
- 禁止把任务完成等同于项目阶段完成；阶段推进仍按独立阶段闸门验收。
- 禁止把本面板描述成聊天客户端底层 UI、强制渲染器或真正的独立后台程序。
