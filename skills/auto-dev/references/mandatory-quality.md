# 固定质量检查

开发助手开启时同时启用三项职责。面板写“规则已启用”，每项实际结果分别写待执行、通过、失败、过期或待复核；开启口令不触发项目扫描、不授权修改，不能冒充检查已完成。

| 职责 | 固定技能 | 执行时点与产物 |
|---|---|---|
| 整体项目审核 | [ponytail-audit](../../ponytail-audit/SKILL.md) | 获准制作后首次接手及每轮开工前，盘点项目入口、构建、依赖、数据与关键路径；保存覆盖范围、问题及未检查部分。轮内沿用有效基线并复核受影响部分，交付记录绑定最终内容。 |
| 每轮代码审核 | [ponytail-review](../../ponytail-review/SKILL.md) | 每个实际制作批次、交付前审核真实差异、调用者、失败路径、权限、状态和冗余；主代理自查与独立只读审核分别记录，修复后复测。 |
| 文字去 AI 味 | [humanizer](../../humanizer/SKILL.md) | 对本轮说明、界面文案、文档与交付文字检查并修改；保留事实、语气和固定面板锚点。没有文字文件变化时核对交付文字，写明范围。 |

首次使用时读取对应完整 SKILL.md 并记录真实路径；缺失时报告缺口，不能声称已执行该技能。以上是固定职责，按时点分步执行；每步仍保持至多一个主技能和两个辅助技能。其它领域技能按项目需要选择，不挤掉固定检查。

代码的可读性、死代码、重复封装、错误处理由 ponytail-review 按项目风格检查。humanizer 处理文字，不承担功能、安全或兼容性验证。固定面板字段与测试证据不因文风润色而删改。

## 证据与交付

JSON 账本新任务采用 qualityVersion=1；旧未完成任务在下一次获准的状态写入时纳入，旧完成历史不改写。show 的 checks[].quality 将规则要求与真实结果分开。运行器增加 project_audit 与 text_review 证据，沿用现有 review 的真实身份、独立性和问题闭环。审核与文字证据保存 skill、source、summary、artifact，绑定计划版本和关注文件指纹；后续失败覆盖早先通过，内容变化后重新复核。

project_audit 使用 skill=ponytail-audit，text_review 使用 skill=humanizer；代码审核使用 kind=review 及既有 reviewer、independent、findings。脚本检查记录完整性，不能证明模型真的阅读、原始报告真实或服务成功。测试数据只能验证约束。

交付前项目审计、代码审核、文字检查和实际测试分别核对。审查不可用就标待复核；不能因测试全绿、赶时间、切换技能或压缩上下文而免掉审核。用户后续明确豁免独立审核时，按原有 review-policy 保存来源、理由和计划版本，面板显示豁免，不冒充审核通过；自查、文字检查、业务测试及开放阻塞问题仍须处理。

## 常见误判

| 情况 | 应有结果 |
|---|---|
| 只说“开发助手” | 开启面板与质量规则，三项待执行，无实施授权 |
| 说“按这个改，快点交付” | 继续理解需求，等待独立“开始制作” |
| 收到独立“开始制作” | 按已明确范围实施并执行固定检查 |
| 测试全绿但审核缺失 | 保留测试证据，交付待复核 |
| 只润色文字 | 如实记录文字范围，不能宣称代码质量已通过 |
