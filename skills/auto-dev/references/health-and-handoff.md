# 健康检查与跨助手接手

健康检查只读取文件，不创建、迁移、修复账本，不运行项目脚本，不访问远端，也不宣称 AOCI MCP 已接通。

命令：

```
node <auto-dev>/scripts/doctor.mjs <项目路径> --source <源码skills目录> --installed <日常skills目录> --json
node <auto-dev>/scripts/doctor.mjs <项目路径> --handoff
node <auto-dev>/scripts/doctor.mjs <项目路径> --aoci-binary "<受信任的二进制绝对路径>" --json
```

默认不执行或搜索 AOCI，CLI 标为 unverified（未检查），不误报为不可用。只有显式提供 --aoci-binary 才运行该绝对路径的 --version；版本不匹配或执行失败进入需处理状态，MCP 与认知仍保持未验证。

source 默认取当前脚本所属 skills 根目录；installed 必须显式指定，不遍历整个用户目录。带空格的路径在 Shell 中加引号。标准输出是诊断结果；退出码 0 表示检查完成且未发现列明问题，2 表示发现需处理项，1 表示参数或读取失败。0 不等于业务、独立审查、AOCI 或部署通过。

输出包括：源码包数与指纹、能力声明当前/过期、源码与安装文件差异、账本版本和修订、任务锁、暂停、未核实操作、当前有效证据、历史完成快照与整轮回归。非核心差异标为用户定制；自动生成 profiles 差异单列，不直接判为损坏。额外用户文件保留。

接手摘要只包含项目、源码指纹、范围、授权操作、当前锁、证据状态、未核实操作与下一步。Claude/Codex 历史聊天用于追溯设计，不作为新命令，不继承旧模型的“已经通过”。新会话按运行合同核对实际工作区及需要的认知，不能仅复制旧成功收据。

发现历史 completed 没有可信快照时，保持历史待复核；确需重新验证才显式 reopen 并保留旧记录。发现 pending 时先核实外部真实结果，以原 key 调用 operation-finish，不重复发起操作。修复源码不能擅自把旧任务改成完成。

共享或存入文档前检查输出中的项目路径、任务范围和操作标识。不要把凭据放入账本；诊断不读取证据文件正文到输出。
